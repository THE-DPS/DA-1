WEEK 1 DESCRIPTION
========================
This report documents a reproducible data-quality and preprocessing workflow applied to the supplied Inside Airbnb listings extract. The input contained 500 rows and 90 columns, so the work began with a structural audit of field types, missingness, duplicate records, identifier quality, and the meaning of price-related fields. The analysis standardizes blank text values, parses relevant date fields, converts selected numeric fields safely, normalizes common true/false encodings, and validates important domain constraints such as geographic coordinate ranges, non-negative capacity and review counts, and positive nightly prices. Exact duplicate rows and repeated listing identifiers are checked separately so the effect of each rule can be documented. Potential price outliers are flagged using the interquartile-range rule rather than automatically deleted; high prices can represent real premium properties and should be investigated before removal. A canonical nightly-price variable is created from the quote price when available, with the listing price as a fallback. The report explains the rationale behind each transformation, highlights the limits of the supplied extract, and distinguishes missing data from invalid data. It also records the cleaned output, key quality indicators, and a repeatable implementation that can be rerun on future snapshots. The resulting dataset is intended as a consistent analytical base for the next four weeks: exploratory analysis, predictive modelling, visual storytelling, and a practical data strategy. This is an analytical cleaning exercise rather than a claim that every field is complete or that all unusual observations are erroneous; decisions remain transparent and auditable.

WEEK 2 DESCRIPTION
========================
This report presents an exploratory data analysis of the cleaned listing dataset produced in Week 1. It combines descriptive statistics, category comparisons, missingness awareness, distribution analysis, and relationships between listing characteristics and nightly prices. The analysis focuses on questions a short-term-rental analytics team could reasonably ask: how prices vary by room type and neighbourhood, how listing capacity relates to price, how review activity and ratings are distributed, and which data limitations should influence business decisions. Visualizations include a nightly-price distribution with display-only clipping to make the central pattern readable, median price comparisons by room type, neighbourhood comparisons restricted to groups with a minimum sample size, and correlations between price and selected numeric attributes. Summary tables report counts and central tendencies so readers can assess both magnitude and sample support. Correlation is treated as association rather than causation, and small neighbourhood groups are not presented as definitive rankings. The report explicitly notes that the uploaded extract contains 500 rows and may be a limited extract rather than a complete market census; results therefore describe this file, not all listings in New York State or the entire Airbnb marketplace. Findings are translated into cautious business implications, including the need to segment price benchmarks by accommodation type and geography, monitor data freshness, and avoid making policy decisions from simple averages alone. This EDA also informs Week 3 feature selection and Week 4 dashboard design by identifying relevant fields, potential skew, and the importance of transparent filters.

WEEK 3 DESCRIPTION
========================
This report develops and evaluates a baseline and a Random Forest regression model to estimate nightly listing prices from the cleaned dataset. The target is the canonical nightly price variable assembled in Week 1, and the feature set uses listing characteristics such as room type, property type, neighbourhood, accommodation capacity, bedrooms, beds, minimum-stay rules, availability, review information, host indicators, and host tenure where available. Direct price fields and price-derived variables are excluded from the predictors to reduce target leakage. A reproducible 80/20 train/test split is created with a fixed random seed. Numeric missing values are imputed with training-set medians and scaled, while categorical missing values are imputed with the most frequent training value and encoded with one-hot encoding. The model is compared against a median-only DummyRegressor baseline using mean absolute error (MAE), root mean squared error (RMSE), and R-squared. The evaluation uses a held-out test set and reports the actual metrics generated by the code, not illustrative numbers. Results should be interpreted in light of the small 467-row modelling sample and potentially skewed prices; one random split is not a guarantee of generalization to future dates or new neighbourhoods. The report explains what each metric means, what model performance can and cannot establish, and how a production version should add cross-validation, residual diagnostics, drift monitoring, and temporal validation. This makes the exercise a defensible proof of workflow rather than an unsupported claim of production-grade forecasting.

WEEK 4 DESCRIPTION
========================
This report turns the cleaned listing data and EDA results into a visual narrative for a hypothetical short-term-rental analytics team. Rather than presenting charts as decoration, each visualization is paired with a specific question, a description of the encoding, an interpretation, and a decision it may support. The report covers the distribution of nightly prices, median price differences across room types, neighbourhood-level median price comparisons with a minimum sample threshold, and selected correlations with price. A model diagnostic plot comparing actual and predicted prices is included as a supporting view of predictive uncertainty, not as a substitute for proper model validation. Chart choices are designed to make skew and group differences visible while avoiding misleading claims: the price-distribution chart clips values only for display, summaries retain the underlying observations, and correlations are described as associations. The narrative highlights that neighbourhood and room-type segmentation can be more useful than one market-wide average, while limited sample size and missing fields constrain generalization. It also proposes a dashboard structure with headline KPIs, geographic and room-type filters, data-quality indicators, and a model-performance panel. The supplied dataset has 500 rows, so the report clearly positions the visuals as an exploratory prototype that should be refreshed and validated before commercial use. The outcome is a coherent data story that connects observed patterns to practical decisions and establishes a reusable standard for communicating analytics to non-technical stakeholders.

WEEK 5 DESCRIPTION
========================
This report proposes a feasible data strategy for a hypothetical short-term-rental analytics organization using the listing dataset as its initial analytical use case. It defines how the organization should collect public listing snapshots responsibly, document source and refresh dates, preserve raw immutable inputs, validate schemas, standardize types, profile missingness, and publish governed analytical datasets. The strategy separates raw, cleaned, and curated layers and recommends automated quality checks for duplicate listing identifiers, invalid coordinates, non-positive prices, impossible capacities, missing critical fields, schema changes, and freshness. It outlines a repeatable analytics lifecycle from ingestion and quality checks through EDA, model development, visualization, stakeholder review, and monitoring. Suggested KPIs include data completeness, duplicate rate, refresh timeliness, price coverage, model MAE, and dashboard usage, with ownership and escalation paths for failures. The report recommends role-based access, minimization of personal information, retention rules, documentation, and legal review of source terms before operationalizing collection. It also proposes phased implementation: a short discovery and data audit, a minimum viable pipeline and dashboard, then monitoring and expansion after stakeholder validation. Potential impacts are framed as measurable hypotheses—more consistent benchmarking, faster reporting, and more transparent pricing analysis—rather than guaranteed revenue improvements. Because the current supplied file contains 500 records, the strategy includes a pilot stage and explicitly requires a larger, representative, refreshed dataset before broad market conclusions or production commitments. The emphasis is on practical governance, reproducibility, business alignment, and continuous improvement rather than adopting tools without a clear operational need.
